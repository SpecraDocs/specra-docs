# Configuration de la recherche

Specra est livré avec une recherche en texte intégral propulsée par [MeiliSearch](https://www.meilisearch.com/). Vous exécutez MeiliSearch vous-même, vous y indexez votre documentation, et Specra l'interroge pour vous. Ce guide décrit l'ensemble du processus.

<Callout type="info">
  **L'index vous appartient.** L'indexation envoie votre contenu vers *votre* serveur MeiliSearch — rien n'est téléversé vers Specra. Une option de recherche hébergée (indexation depuis le CLI, servie sur un sous-domaine Specra) est prévue dans la feuille de route ; pour l'instant, la recherche est auto-hébergée.
</Callout>

## Options de recherche

| Option | Configuration | Idéal pour |
|--------|-------|----------|
| **Recherche locale** (par défaut) | Aucune | Petits sites ; recherche dans le navigateur |
| **MeiliSearch** (recommandé) | Exécuter un serveur + indexer | Sites moyens/grands ; résultats instantanés, tolérants aux fautes de frappe et adaptés à la langue |

Le reste de ce guide couvre MeiliSearch. Si vous souhaitez simplement une recherche sans configuration, passez à [Recherche locale](#recherche-locale-alternative).

## Comment tout s'articule

```txt
Browser  ──GET /api/search?q=…──▶  Votre app Specra (serveur)  ──▶  Votre serveur MeiliSearch
   ▲                                        │
   └──────────── résultats ◀────────────────┘
```

Le navigateur ne communique jamais qu'avec la route `/api/search` de votre propre application. Cette route s'exécute sur le serveur, lit vos identifiants MeiliSearch depuis `specra.config.json`, et transmet la requête. Votre hôte MeiliSearch et votre clé API ne sont **jamais exposés au navigateur**, et il n'y a aucun problème d'origine croisée (CORS).

## Démarrage rapide

**Prérequis :** votre site de documentation Specra (déjà configuré) et un serveur MeiliSearch (nous en démarrons un ci-dessous).

### 1. Exécuter un serveur MeiliSearch

Choisissez la méthode la plus simple pour vous.

**Option A — binaire autonome (sans Docker, sans root) :**

```bash
# Télécharger le binaire dans le dossier courant
curl -L https://install.meilisearch.com | sh

# L'exécuter avec une clé maître (choisissez la vôtre)
./meilisearch --master-key="aSampleMasterKey" --http-addr=127.0.0.1:7700
```

**Option B — Docker :**

```bash
docker run -d \
  --name meilisearch \
  -p 7700:7700 \
  -e MEILI_MASTER_KEY="aSampleMasterKey" \
  -v $(pwd)/meili_data:/meili_data \
  getmeili/meilisearch:latest
```

Dans les deux cas, MeiliSearch écoute désormais sur `http://localhost:7700`. Vérifiez-le :

```bash
curl http://localhost:7700/health
# {"status":"available"}
```

<Callout type="warning">
  `aSampleMasterKey` est réservé au développement local uniquement. Utilisez une clé maître longue et aléatoire en production.
</Callout>

### 2. Activer la recherche dans specra.config.json

Pointez Specra vers votre serveur. La clé `apiKey` ici sert à la fois à l'indexation et à l'interrogation, donc pour le développement local, définissez-la sur la **même valeur** que votre clé maître MeiliSearch.

```json
{
  "search": {
    "enabled": true,
    "provider": "meilisearch",
    "placeholder": "Search documentation...",
    "meilisearch": {
      "host": "http://localhost:7700",
      "apiKey": "aSampleMasterKey",
      "indexName": "docs"
    }
  }
}
```

### 3. Indexer votre contenu

Specra est livré avec un indexeur. Depuis la racine de votre projet :

```bash
npm run index:search
```

Il lit `specra.config.json`, parcourt chaque version et chaque locale sous `docs/`, extrait le texte cherchable, et pousse les documents vers votre serveur MeiliSearch. Relancez-le à chaque modification de votre documentation.

<Callout type="info">
  L'indexation est asynchrone du côté de MeiliSearch. Attendez quelques secondes, puis vérifiez avec `npm run test:search`.
</Callout>

### 4. Essayer

Démarrez votre serveur de développement et ouvrez la boîte de recherche avec **⌘K** (macOS) ou **Ctrl+K** (Windows/Linux) :

```bash
npm run dev
```

Commencez à taper pour voir des résultats instantanés.

## Référence de configuration

Tous les paramètres se trouvent sous `search` dans `specra.config.json` :

| Champ | Type | Description |
|-------|------|-------------|
| `enabled` | boolean | Activer ou désactiver la recherche |
| `provider` | `"meilisearch"` \| `"local"` | Moteur de recherche |
| `placeholder` | string | Texte indicatif dans la boîte de recherche |
| `meilisearch.host` | string | URL de votre serveur MeiliSearch |
| `meilisearch.apiKey` | string | Clé utilisée pour indexer et pour interroger |
| `meilisearch.indexName` | string | Nom de l'index (par ex. `docs`) |

## Recherche adaptée à la langue

Si votre site utilise l'i18n, la recherche est automatiquement limitée à la langue du lecteur — sans configuration supplémentaire. L'indexeur stocke un champ `locale` sur chaque document, et `/api/search` filtre les résultats selon la langue que le lecteur consulte actuellement, de sorte qu'une personne lisant la documentation française ne voit que les résultats en français. Le sélecteur de langue de l'en-tête et la recherche restent synchronisés.

## Production

### Héberger MeiliSearch

Pour la production, vous hébergez MeiliSearch quelque part où votre application peut l'atteindre :

- **[MeiliSearch Cloud](https://www.meilisearch.com/cloud)** — géré, avec sauvegardes et mises à jour automatiques.
- **Votre propre VPS** (DigitalOcean, AWS, Fly.io, Railway, Render…) — exécutez le binaire ou l'image Docker, idéalement derrière HTTPS.

Définissez ensuite `meilisearch.host` sur l'URL de ce serveur.

### Utiliser une clé au privilège minimal

Comme les requêtes passent par votre `/api/search` côté serveur, la clé `apiKey` n'atteint jamais le navigateur. Malgré tout, donnez à l'application une clé **en lecture seule (recherche uniquement)** et réservez la clé maître à l'indexation.

Créez une clé de recherche uniquement à partir de votre clé maître :

```bash
curl -X POST 'https://your-meilisearch-host/keys' \
  -H 'Authorization: Bearer YOUR_MASTER_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{
    "description": "Search key for docs",
    "actions": ["search"],
    "indexes": ["docs"],
    "expiresAt": null
  }'
```

Utilisez la clé renvoyée comme `meilisearch.apiKey` dans votre `specra.config.json` de production, et indexez avec la clé maître (voir la section CI ci-dessous).

### Indexer au déploiement (CI/CD)

L'indexeur lit son hôte et sa clé depuis `specra.config.json`. Pour indexer avec votre **clé maître** en CI sans la committer, générez la configuration (ou écrasez la clé) au moment de la compilation à partir d'un secret. Une tâche GitHub Actions minimale :

```yaml
name: Index docs
on:
  push:
    branches: [main]
    paths: ['docs/**']

jobs:
  index:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      # Injecter la clé maître dans la configuration uniquement pour l'indexation
      - run: |
          node -e "const f='specra.config.json',c=require('./'+f);
            c.search.meilisearch.host=process.env.MEILI_HOST;
            c.search.meilisearch.apiKey=process.env.MEILI_MASTER_KEY;
            require('fs').writeFileSync(f, JSON.stringify(c,null,2));"
        env:
          MEILI_HOST: ${{ secrets.MEILI_HOST }}
          MEILI_MASTER_KEY: ${{ secrets.MEILI_MASTER_KEY }}
      - run: npm run index:search
```

Livrez votre application avec la clé **de recherche uniquement** dans `specra.config.json`, et laissez la CI substituer la clé maître uniquement pour l'étape d'indexation.

## Personnaliser l'index

Le comportement d'indexation se trouve dans `scripts/index-search.ts`. Il configure MeiliSearch de la manière suivante aujourd'hui :

```ts
await index.updateSearchableAttributes(["title", "content", "tags"])
await index.updateFilterableAttributes(["version", "locale", "category", "tags"])
await index.updateSortableAttributes(["title"])
await index.updateDistinctAttribute("id")
await index.updateSettings({
  rankingRules: ["words", "typo", "proximity", "attribute", "sort", "exactness"],
})
```

Modifiez ce script pour changer ce qui est cherchable, ajouter des synonymes ou des mots vides, ou ajuster le classement — puis relancez `npm run index:search`.

## Recherche locale (alternative)

Vous ne voulez pas exécuter de serveur ? Utilisez la recherche locale intégrée :

```json
{
  "search": {
    "enabled": true,
    "provider": "local",
    "placeholder": "Search documentation..."
  }
}
```

- ✅ Fonctionne immédiatement, sans serveur, gratuit
- ❌ Pas de tolérance aux fautes de frappe, classement plus faible, plus lent sur les grands sites

## Raccourcis clavier

- **⌘K** / **Ctrl+K** — ouvrir la recherche
- **↑ / ↓** — se déplacer entre les résultats
- **Enter** — ouvrir le résultat sélectionné
- **Esc** — fermer la recherche

## Dépannage

**La boîte de recherche n'apparaît pas** — confirmez que `search.enabled` est `true` dans `specra.config.json`.

**MeiliSearch inaccessible** — vérifiez le serveur :

```bash
curl http://localhost:7700/health   # attendu {"status":"available"}
```

**Aucun résultat** — réindexez et confirmez que l'index existe :

```bash
npm run index:search
curl -H "Authorization: Bearer YOUR_KEY" http://localhost:7700/indexes
```

**`/api/search` renvoie « Search is not enabled »** — la route lit `specra.config.json` ; assurez-vous que `enabled` est `true` et que `provider` est `"meilisearch"`, puis redémarrez le serveur de développement pour que la configuration soit relue.

**Résultats dans la mauvaise langue** — relancez `npm run index:search` pour que chaque document reçoive son champ `locale`.
