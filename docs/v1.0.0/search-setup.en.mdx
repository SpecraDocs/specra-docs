# Setting Up Search

Specra ships with full-text search powered by [MeiliSearch](https://www.meilisearch.com/). You run MeiliSearch yourself, index your docs into it, and Specra queries it for you. This guide walks through the whole flow.

<Callout type="info">
  **You own the index.** Indexing sends your content to *your* MeiliSearch server — nothing is uploaded to Specra. A hosted search option (index from the CLI, served on a Specra subdomain) is on the roadmap; for now, search is self-hosted.
</Callout>

## Search Options

| Option | Setup | Best for |
|--------|-------|----------|
| **Local search** (default) | None | Small sites; searches in the browser |
| **MeiliSearch** (recommended) | Run a server + index | Medium/large sites; instant, typo-tolerant, language-aware results |

The rest of this guide covers MeiliSearch. If you just want zero-config search, jump to [Local Search](#local-search-alternative).

## How it fits together

```txt
Browser  ──GET /api/search?q=…──▶  Your Specra app (server)  ──▶  Your MeiliSearch server
   ▲                                        │
   └──────────── results ◀──────────────────┘
```

The browser only ever talks to your own app's `/api/search` route. That route runs on the server, reads your MeiliSearch credentials from `specra.config.json`, and forwards the query. Your MeiliSearch host and API key are **never exposed to the browser**, and there are no cross-origin (CORS) concerns.

## Quick Start

**Prerequisites:** your Specra docs site (already set up) and a MeiliSearch server (we start one below).

### 1. Run a MeiliSearch server

Pick whichever is easiest for you.

**Option A — standalone binary (no Docker, no root):**

```bash
# Download the binary into the current folder
curl -L https://install.meilisearch.com | sh

# Run it with a master key (choose your own)
./meilisearch --master-key="aSampleMasterKey" --http-addr=127.0.0.1:7700
```

**Option B — Docker:**

```bash
docker run -d \
  --name meilisearch \
  -p 7700:7700 \
  -e MEILI_MASTER_KEY="aSampleMasterKey" \
  -v $(pwd)/meili_data:/meili_data \
  getmeili/meilisearch:latest
```

Either way, MeiliSearch is now listening on `http://localhost:7700`. Verify it:

```bash
curl http://localhost:7700/health
# {"status":"available"}
```

<Callout type="warning">
  `aSampleMasterKey` is for local development only. Use a long, random master key in production.
</Callout>

### 2. Enable search in specra.config.json

Point Specra at your server. The `apiKey` here is used both to index and to query, so for local development set it to the **same value** as your MeiliSearch master key.

```json
{
  "search": {
    "enabled": true,
    "provider": "meilisearch",
    "placeholder": "Search documentation...",
    "meilisearch": {
      "host": "http://localhost:7700",
      "apiKey": "aSampleMasterKey",
      "indexName": "docs"
    }
  }
}
```

### 3. Index your content

Specra ships an indexer. From your project root:

```bash
npm run index:search
```

It reads `specra.config.json`, walks every version and locale under `docs/`, extracts the searchable text, and pushes the documents to your MeiliSearch server. Re-run it whenever your docs change.

<Callout type="info">
  Indexing is asynchronous on MeiliSearch's side. Wait a couple of seconds, then verify with `npm run test:search`.
</Callout>

### 4. Try it

Start your dev server and open the search box with **⌘K** (macOS) or **Ctrl+K** (Windows/Linux):

```bash
npm run dev
```

Start typing to see instant results.

## Configuration reference

All settings live under `search` in `specra.config.json`:

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | boolean | Turn search on or off |
| `provider` | `"meilisearch"` \| `"local"` | Search backend |
| `placeholder` | string | Placeholder text in the search box |
| `meilisearch.host` | string | URL of your MeiliSearch server |
| `meilisearch.apiKey` | string | Key used to index and to query |
| `meilisearch.indexName` | string | Index name (e.g. `docs`) |

## Language-aware search

If your site uses i18n, search is scoped to the reader's language automatically — no extra setup. The indexer stores a `locale` field on every document, and `/api/search` filters results to the language the reader is currently viewing, so someone reading the French docs only sees French hits. The header language switcher and search stay in sync.

## Production

### Host MeiliSearch

For production you host MeiliSearch somewhere your app can reach it:

- **[MeiliSearch Cloud](https://www.meilisearch.com/cloud)** — managed, automatic backups and updates.
- **Your own VPS** (DigitalOcean, AWS, Fly.io, Railway, Render…) — run the binary or the Docker image, ideally behind HTTPS.

Then set `meilisearch.host` to that server's URL.

### Use a least-privilege key

Because queries go through your server-side `/api/search`, the `apiKey` never reaches the browser. Even so, give the app a **search-only** key and keep the master key for indexing.

Create a search-only key from your master key:

```bash
curl -X POST 'https://your-meilisearch-host/keys' \
  -H 'Authorization: Bearer YOUR_MASTER_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{
    "description": "Search key for docs",
    "actions": ["search"],
    "indexes": ["docs"],
    "expiresAt": null
  }'
```

Use the returned key as `meilisearch.apiKey` in your production `specra.config.json`, and index with the master key (see CI below).

### Index on deploy (CI/CD)

The indexer reads its host and key from `specra.config.json`. To index with your **master key** in CI without committing it, generate the config (or overwrite the key) at build time from a secret. A minimal GitHub Actions job:

```yaml
name: Index docs
on:
  push:
    branches: [main]
    paths: ['docs/**']

jobs:
  index:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      # Inject the master key into the config just for indexing
      - run: |
          node -e "const f='specra.config.json',c=require('./'+f);
            c.search.meilisearch.host=process.env.MEILI_HOST;
            c.search.meilisearch.apiKey=process.env.MEILI_MASTER_KEY;
            require('fs').writeFileSync(f, JSON.stringify(c,null,2));"
        env:
          MEILI_HOST: ${{ secrets.MEILI_HOST }}
          MEILI_MASTER_KEY: ${{ secrets.MEILI_MASTER_KEY }}
      - run: npm run index:search
```

Ship your app with the **search-only** key in `specra.config.json`, and let CI swap in the master key only for the indexing step.

## Customizing the index

Indexing behavior lives in `scripts/index-search.ts`. It configures MeiliSearch like this today:

```ts
await index.updateSearchableAttributes(["title", "content", "tags"])
await index.updateFilterableAttributes(["version", "locale", "category", "tags"])
await index.updateSortableAttributes(["title"])
await index.updateDistinctAttribute("id")
await index.updateSettings({
  rankingRules: ["words", "typo", "proximity", "attribute", "sort", "exactness"],
})
```

Edit that script to change what's searchable, add synonyms or stop words, or tune ranking — then re-run `npm run index:search`.

## Local search (alternative)

Don't want to run a server? Use built-in local search:

```json
{
  "search": {
    "enabled": true,
    "provider": "local",
    "placeholder": "Search documentation..."
  }
}
```

- ✅ Works immediately, no server, free
- ❌ No typo tolerance, weaker ranking, slower on large sites

## Keyboard shortcuts

- **⌘K** / **Ctrl+K** — open search
- **↑ / ↓** — move between results
- **Enter** — open the selected result
- **Esc** — close search

## Troubleshooting

**Search box doesn't appear** — confirm `search.enabled` is `true` in `specra.config.json`.

**MeiliSearch unreachable** — check the server:

```bash
curl http://localhost:7700/health   # expect {"status":"available"}
```

**No results** — re-index and confirm the index exists:

```bash
npm run index:search
curl -H "Authorization: Bearer YOUR_KEY" http://localhost:7700/indexes
```

**`/api/search` returns "Search is not enabled"** — the route reads `specra.config.json`; make sure `enabled` is `true` and `provider` is `"meilisearch"`, then restart the dev server so the config is re-read.

**Wrong-language results** — re-run `npm run index:search` so each document gets its `locale` field.
